# Handshake flow control — sound kernel synthesis + whole-system verification

The second example in the mununu control-kernel corpus (after the bus arbiter in
`../agentic_rtl_loop/`). Same loop, a different control pattern: **dataflow
backpressure**. The datapath sub-modules (a producer, a bounded FIFO, a
consumer) are hand/LLM-written SystemVerilog; the **flow-control kernel is
synthesized correct-by-construction** and mununu **verifies the whole assembled
system**.

Backpressure is the control pattern where LLM-written RTL most often deadlocks or
loses data — you cannot sample your way to "never overflows" or "never stalls."

## The loop

```
requirement.md  ──prompt.md──▶  flow_ctrl.tlsf  ──mununu synth──▶  flow_ctrl.sv
   (English)        (LLM)          (spec)         (sound GR(1))    (correct-by-construction)
                                                                        │
  producer.sv + fifo.sv + consumer.sv (LLM-authored datapath) ──assemble──▶ system.sv
                                                                        │
                                                            mununu verify (sv2v+yosys+btormc)
                                                                        ▼
                    no overflow ✓  no underflow ✓  no drop ✓  no phantom ✓  eager ✓  discharge ✓
```

## The pieces

| File | Role | Who writes it |
|---|---|---|
| `requirement.md` | the plain-English flow-control requirement | the designer / upstream agent |
| `prompt.md` | the reusable NL → TLSF prompt | the loop |
| `flow_ctrl.tlsf` | the control-kernel spec | the LLM, via `prompt.md` |
| `producer.sv` | offers items, holds until accepted | LLM-authored datapath |
| `fifo.sv` | a depth-2 bounded FIFO with protocol SVA | LLM-authored datapath |
| `consumer.sv` | applies backpressure, but is fair (ready every other cycle) | LLM-authored datapath |
| `system.sv` | the top: datapath + kernel + verification monitors | assembly |
| `flow_ctrl.sv` | the **synthesized** kernel | **mununu** (generated by `run.sh`) |
| `run.sh` / `verify.sh` | synthesize → assemble → verify | the loop |

## Run it

```bash
./run.sh          # needs `mununu` on PATH + the mununu-sva docker image
```

## What is verified

**Safety + assume-guarantee discharge — k-induction (sound, unbounded):**

- `bad_overflow` — never enqueue into a full FIFO. **(the no-data-loss headline)**
- `bad_underflow` — never dequeue an empty FIFO.
- `bad_drop` — never dequeue unless the consumer takes it (no lost item).
- `bad_phantom` — never accept an item the producer didn't offer.
- `bad_assume_cready` — the consumer **discharges** the kernel's `G F c_ready`
  assumption (it is ready at least every other cycle). This is the compositional
  payoff: the kernel is correct *under* its fairness assumption, and the concrete
  consumer *supplies* that fairness.

**Liveness — bounded model checking to depth 100:**

- `bad_stall_enq`, `bad_stall_deq` — **eager transfer**: the kernel never leaves a
  transferable item waiting more than one cycle. Verified by bounded model
  checking (no stall reachable within 100 cycles).

  > Honesty note. Unlike the arbiter's no-starvation, this eager-transfer property
  > is **not k-inductive** in the integrated system: the `enq ↔ FIFO-occupancy ↔
  > full` feedback loop resists a simple inductive invariant, and the toolchain
  > here (sv2v/yosys) does not lift `s_eventually` for a justice-based liveness
  > proof. So we report it honestly as a **bounded** check, not an unbounded
  > proof. The safety guarantees above — including no-data-loss — are the sound,
  > unbounded results.

## Negative control

The verification is not vacuous. Swap the synthesized kernel for a broken one
that enqueues whenever the producer offers (ignoring `full`), and `bad_overflow`
becomes **`sat`** — the check discriminates.

## A note on the spec (a real fragment edge)

The natural drain guarantee "every buffered item eventually leaves"
(`G (!empty -> F deq)`) is **genuinely unrealizable** under a free-input FIFO
abstraction: an adversary can correlate `c_ready` with `empty` so that draining is
never enabled while still satisfying `G F c_ready`. The realizable — and honest —
form narrows each response's trigger to its **enabling condition**
(`G ((!empty && c_ready) -> F deq)`): the kernel must act when it *can*, and the
fair environment (a real consumer) then supplies the opportunities. This is the
GR(1)-fragment discipline the corpus plan calls out.

## Honest scope

- A **constructed demo system**, not a finding about a real chip.
- The kernel is in the **GR(1) reactive-control fragment**; the FIFO is abstracted
  to fair `full`/`empty` inputs, discharged by the concrete FIFO + consumer.
- The **NL → TLSF leg is done by an LLM** (`prompt.md`); `flow_ctrl.tlsf` is an
  example output. mununu owns the synthesis and verification legs.

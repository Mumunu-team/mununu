## Surprises / dead-ends

- macOS bash `set -e` interacts with `tar --use-compress-program=zstd` if zstd isn't installed; `bench_record.sh` will need a graceful fallback to gzip, plus a check at startup. Punting: will add when running EXP-0001 and discovering it on a clean machine. **Status (sitting 2): zstd was available on the host; archive wrote successfully.**
- `Makefile` `%:` catch-all for `bench-record EXP=... -- <args>` is a known make-ism. It works but emits a "warning: overriding recipe" that I'm ignoring; if it gets noisy in CI, switch to a wrapper script that consumes the rest of `$*`. **Status (sitting 2): bench_record.sh is being invoked directly from the shell, not via `make bench-record`, so the warning hasn't surfaced. If CI hits it, switch then.**
- `cargo`'s bench auto-detection treats every `benches/*.rs` as a target. The leading underscore in `_common.rs` did not exempt it. Resolution: shared bench helpers live at `crates/mununu-core/src/bench_support.rs` (gated by `test_support` feature), not in `benches/`.
- `StateId<u32>` does not implement `TryFrom<usize>`; only `from_index(usize) -> Option<Self>`. Caught during `cargo test --features test_support` of the new templates. The error message is clear; not a problem, just a friction worth noting for newcomers.
- `compose()` takes `&CompositionOptions`, not owned. Fixed in benches.
- `minimize_bisimulation` is at `composition::minimize::minimize_bisimulation`, not re-exported from `composition`. Used the qualified path. If a future refactor flattens this, multiple benches need to track the change in lock-step.
- EXP-0001's `criterion-archive.tar.zst` ended up containing data for all four subsystems even though the manifest's `command` field names only `clts_construction`. Cause: `target/criterion/` accumulates across runs. Fix: `--fresh` flag on `bench_record.sh`, used by all EXPs starting at EXP-0002. Documented in `experiments/EXP-0001-baseline-cliff/notes.md`.

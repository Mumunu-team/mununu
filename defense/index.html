We verify the security properties assertions cannot express.

For defense hardware, one question decides everything: once a security chip trips into a locked-down state, can an attacker ever coax it back out? Mununu answers that soundly, entirely on your own machines — and admits when it can’t, instead of a false “secure.”

Technical detail

Trusted-microelectronics programs turn on a single question — once a security FSM has escalated, can it ever be walked back? That is a branching-time question, and Mununu answers it soundly, on your own premises, on real root-of-trust RTL. When it cannot know, it says so — ⊥, never a comforting, false “secure.”

The problem

The assurance gap

The tools that vet secure chips assume the cloud and charge per seat — a bad fit for classified work — and worse, they can quietly guess and still show a green checkmark. Mununu runs fully offline and never guesses.

Technical detail

Commercial formal tools are licensed by the seat and lean, more each year, on the cloud — an awkward guest in classified and air-gapped programs, where every tool must live wholly inside the enclave and answer for itself down to the byte.

Worse than the licensing is the epistemics. In security verification the nightmare is the silent wrong “pass” — a tool that quietly approximates, then reports “secure,” is a liability wearing a green checkmark.

Mununu is built for the opposite stance: on-prem, written in Rust, on an open-source toolchain, deployable with no network at all. Its verdicts are three-valued — True, False, or ⊥ (undecided) — and when abstraction cannot carry a definite answer, it abstains. It never bluffs.

The differentiated wedge

“Can it recover — or does it latch into the trap?”

A security chip has to do two opposite things perfectly: always recover under normal use, and never recover once it’s been attacked. Mununu proves both — on the same real chip.

AG EF idle From every reachable state, does a path back to idle still exist?
Technical detail

For a security state machine, recoverability cuts both ways. In ordinary operation, with reset available, idle must stay within reach — a wedged security controller is a denial of service. But the instant the escalation input fires, the design must not recover: latching into the error trap is the whole point of the guard.

Both directions are branching-time. SystemVerilog Assertions and LTL bounded model checkers cannot say “a path back always exists,” so they can confirm neither the recovery nor the trap. Mununu decided both, definitively, on a production OpenTitan security FSM — the same real RTL, two environments, two sound verdicts.

Beyond checking

And synthesize the control kernel

Beyond checking someone’s work, Mununu can build the security control logic itself — so it’s correct by construction — and hands back machine-readable evidence when something fails.

Technical detail

For security-critical sequencing — lockstep steps, key-handling phases, escalation ladders — Mununu can synthesize the controller correct-by-construction instead of grading a hand-written one after the fact. What comes back is a control kernel that cannot violate its specification, because it was never shaped able to.

And when a property does fail, Mununu hands back structured JSON counterexamples — machine-readable traces made for triage tooling, not waveforms for a human to squint at.

# Consumer briefing — mununu 0.5.0: the migration cheat sheet (2026-10)

> Source of truth: the 0.5 surface-cohesion review [`docs/design/surface-cohesion-0.5.md`](../design/surface-cohesion-0.5.md) and the per-cluster briefings linked below — surface: (CLI+API+UI)

**Audience:** the maintainers of rosf, monono and mununu-ui migrating to mununu 0.5.0 this week, and anyone else who calls mununu. 0.5 is a declared clean break: no aliases, every rename at once. This page is the one checklist; each row links the briefing that explains why.

## TL;DR

- **Version: pin `0.5.7` (or at least `0.5.1`).** 0.5.0 mapped `--frontend sv2v` to a forced `read_verilog`, losing the slang fallback that lifts `bind` checkers; 0.5.1 restores it ([briefing](2026-10-frontend-sv2v-fallback-0.5.1.md)). Pin it exactly, as rosf pinned `0.4.0`.
- **0.5.3 fixes two soundness defects; take it.** A mux on internal logic shaped like a reset mux was read as the register behind it, a false VIOLATED ([briefing](2026-10-reset-mux-alias.md)); a black box's outputs were frozen on the cube engines, a false HOLDS ([briefing](2026-10-nextless-states-free.md)). It also returns the trap as a `trace` from `verify-recoverability`, starts a pinned reset from the reset state ([briefing](2026-10-recoverability-trace.md)), and applies bounded-sequence assumptions as preconditions ([briefing](2026-10-assume-chains.md)).
- **0.5.4 adds `@mununu_guarantee ltl …`** — LTL bodies in SystemVerilog annotations, read over every path, with comparison atoms in the LTL parser ([briefing](2026-10-ltl-annotation-bodies.md)); the exact engine no longer panics (its extractors abstain with a reason) and its fixpoint polls the caller's run budget; rIC3's IC3 finds the shallow witness first. Additive for every consumer.
- **0.5.5 adds `make trace` to the generated replay testbench** — the same Verilator replay writes `replay.vcd` for GTKWave; the default `make` is unchanged ([briefing](2026-10-replay-vcd-trace.md)). Additive.
- **0.5.6 makes a violated `ltl … W …` annotation ship its path, and keeps the per-property notes the verdict passes push** — the weak-until is translated in the spelling the safety-witness monitor compiles, and the report's notes rebuild no longer discards a `witness-unavailable` (or `expression-leaf-unresolved`, `engine-isolation`, `array-atom-unsupported`, `antecedent-*`) note ([briefing](2026-10-ltl-weak-until-witness.md)); verdicts unchanged.
- **0.5.7 reads back to the RTL.** An `@mununu_guarantee ltl …` row shows its formula as written, with the mu-calculus beside it (`formula_language`, `translated`; the row's `formula` value changes for `ltl` rows only — [briefing](2026-10-ltl-annotation-formula-as-written.md)); `--replay` / `replay: true` runs the Verilator testbench from mununu and reports it on the row, and `replay.gtkw` opens GTKWave on the trace's signals ([briefing](2026-10-replay-run-and-gtkw.md)); every counterexample ends with a `cells:` legend naming where its registers and inputs live in the RTL (`trace.sources`), and `diagnostics.source_map` — a new required key — says when the map is unavailable (sv2v preprocessing) ([briefing](2026-10-rtl-source-lines-legend.md)). Additive otherwise.
- **0.5.2 is additive over 0.5.1, with no verdict changes:** `sv verify-auto` traces list the design's registers under the design's names, with the verifier's cells under `steps[].monitor`, fault injections on `steps[].faults` and no clock among the inputs; `sv mutate` reports `outcome` and the SVA `label`s, and `--list` names targets the design's way ([briefing](2026-10-readable-traces.md)); `verify-recoverability` gains `--pin` / API `pins` ([briefing](2026-10-recoverability-pin.md)).
- **Exit codes:**
  - `0` means pass, `1` a tool error, `2` violated, `3` unknown under `--fail-on unknown`, and `4` unmet expectations.
  - **`64` is new and means a usage error**; it used to be `2`, the same as violated.
  - `context eval` and `verify` now gate on their verdict.
- **Verdict field:** every deciding verb reports **`outcome`**.
- **Counterexamples:** every path is one **`Trace`**.
- **Lift input:** the `sv` verbs share one lift-flag set, and the API takes one `lift` object.

## The cheat sheet

|---|---|---|
| a usage error exits `2` | exits `64` | [exit codes](2026-10-exit-codes-0.5.md) |

| `verify-recoverability --config-values N=v1,v2` | `--partition N=v1,v2` | [flags a](2026-10-flags-pin-partition-0.5.md) |

## Per consumer

| consumer | what to change | done when |
|---|---|---|
| **rosf** | adapter: `--config-value` → `--pin` in `build_args` and the `--help` probe; `tested: "0.5.0"`; map exit `64` to `skipped` like `1`; `toolchain.lock` `mununu = "0.5.0"`; `docs/tool-contracts.md`; recapture `tests/fixtures/captured/mununu-<0.5 hash>/`; the cheatsheet reads `outcome` / `trace` | rosf CI green against the 0.5 binary in its image |
| **monono** | lanes: `--pin`, `--frontend sv2v`, `sv verify-bad`, the `verify-liveness` flag forms; `verify --json` `outcome`; replace the `Initial states satisfying:` greps with `context eval --json \| jq -r .outcome`; add `--fail-on none` where a lane reads the verdict itself | monono's verify lanes green on the 0.5 image |
| **mununu-ui** | `src/api/endpoints.ts`: the route renames; `lift` objects on the `sv` requests; `outcome` instead of `verdict` / `satisfied` / `all_satisfied`; `cells` on cegar; one `Trace` renderer for the cegar, game, btor2-verify, lasso, deadlock and sanity views; GR(1) through `/context/synth` | `npm test` and `tsc` green against the 0.5 dev backend |

## Verification steps for every consumer

```bash
mununu --version                                         # 0.5.0
mununu sv verify-auto --config-value x=1; echo $?        # 64: the old flag is a usage error
mununu sv verify-auto top.sv --top top --pin rst_ni=1 --json | jq '.properties[] | {name, outcome, trace: .trace.kind}'
mununu context eval m.ctxdsl --automaton A --formula f --json | jq -r .outcome
```

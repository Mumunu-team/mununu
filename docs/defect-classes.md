# Defect classes

> Source of truth: [`scripts/pr_review_gate.py`](../scripts/pr_review_gate.py) (`CATALOG_HEADING`: a fix's `Class: <slug>` must name a `###` heading of this file) — surface: CLI-only — a contributor instrument

The catalogue behind [`policies/fix-the-class.md`](policies/fix-the-class.md). One entry per class: **what varies**, the **cases**, what the code does on each, the **test that enumerates them**, and the fixes that have landed in the class. A fix in a class updates its entry; a fix that meets an unlisted case adds it.

The first seven entries were seeded on 2026-11-20 from the fix chains of the two weeks before. Their case tables record what those fixes covered. **They have not yet been checked against the code that produces the cases** — the first fix in each class does that and removes this caveat from the entry.

An entry's heading is `### ` followed by the slug in backticks; the gate reads exactly that.

---

### `abandoned-request-work`

**What varies:** the work an HTTP request started that can outlive its response once the request times out or the client goes away: the handler body on the blocking pool, the engine threads and per-property budgets under it, the subprocess children, a thread with no budget poll, an MCP tool call.

| a subprocess child (yosys, btormc, Pono, rIC3) | the helper polls the flag and kills the child, returning `Interrupted` with the reason | mununu#1147 |

### `clock-net-driver`

**What varies:** what drives a net a flop or memory port is clocked by, after the walk through inverters and buffers — read off the netlist the lift's script writes after `delete =A:mununu_missing_module; cutpoint -blackbox; flatten`, on a copy cleaned by an `opt_clean` that keeps every named net (`cleaned-netlist-coverage` below) (`ClockDrivers::root_of` → `ClockRoot` in `adapter/yosys/mod.rs`). The BTOR2 model has one implicit clock, so every root but a top-level input is an abstraction decision; the repository's rule for the lockstep reading is an explicit opt-in (`--merge-clock-domains` on the seven `sv` verbs that take it, API `lift.merge_clock_domains`), refused without it. The two black-box shapes were measured in `mununu-sva` on 2026-11-20 (the fixtures of the enumerating tests are those captures; the e2e re-lifts both). The shapes of mununu#1180 were measured there on 2026-11-22 (ten captured netlists with their hierarchy snapshots; the e2e re-lifts seven of the sources). A stub's port directions are not in the flattened netlist — yosys writes none for a cell of unknown type — so the lift's scan reads them from the hierarchy snapshot it takes before the stubs are deleted (`clock_domains_with_hierarchy`).

### `cleaned-netlist-coverage`

**What varies:** what reads a storage cell, which decides whether a copy of the design cleaned by yosys's `opt_clean` still holds it. `opt_clean` keeps the cone of the output ports. `write_btor` writes more: the cone of the output ports and of every wire whose name does not start with `$` (a named wire becomes a named node and pulls its drivers in). So a copy cleaned by a bare `opt_clean` holds less than the model, and whatever reads the copy answers for a smaller design. The lift cleans two copies: the one the clock scan reads (`clocks.json`, which `sv cdc-lint`, the source map and the counterexample slice read too) and, on the backend's "topological loop" error, the design the retry writes the model from. Since mununu#1229 one pass marks every named net `keep` before each `opt_clean` (`KEEP_NAMED_NETS` in `adapter/yosys/mod.rs`), which is the backend's rule. A keep on every storage cell was tried first and rejected: it counts a flop the model has dropped (the `--cutpoint` row below). Each row was run by hand with the yosys of `mununu-sva` (0.68+120) on 2026-11-23, on the sources of the enumerating test; the design is two flops on two clocks, and the row says what reads the second domain's storage.

### `lift-decision-report`

**What varies:** two things. First, what a SystemVerilog lift decides besides the model — enumerated from what the lift is asked and what it returns (`YosysOptions`, `SvLiftResult` in `adapter/yosys/mod.rs`, and the flop stubs `sv verify-auto`'s lift adds): the modules it cut because the sources hold no body for them, the nets the request asked it to cut, the parameters the request set, whether its yosys script ran twice, the flop primitives it supplied a model for, the clock domains (their own class, [`clock-net-driver`](#clock-net-driver)), the sources a lift override replaced, and the value it reads an `x` constant as. Second, the verb or entry whose result is read on that model: a decision is a fact about the model, so a report that drops one states a result on a design the reader did not ask about. What a cut means is not the same for every verb — a free net is an over-approximation, which keeps a HOLDS of a property over every run, keeps neither verdict of `AG EF`, and for a scan or a lint changes what was looked at — so the note is worded per reader (`LiftReader` in `adapter/lift_decisions.rs`, one exhaustive `match`). The two meet in the clock notes: a model that ticks every clock on every step lacks runs of the design, so a lift with a clock note and a free net is neither an over- nor an under-approximation, and each reader has a second wording for that case (a second exhaustive `match`).

| Case | Behaviour | Landed |
